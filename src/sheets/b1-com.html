  • Two's complement n บิต: ช่วง −2^(n−1) ถึง 2^(n−1)−1 (8 บิต −128…127 · unsigned 0…255) · หา −X = กลับบิตของ X แล้ว +1

  • เลข 10 ในฐาน 2 คือสอง ไม่ใช่สิบ · 1 KB = 1,000 B เฉพาะเมื่อโจทย์ระบุฐาน SI

  • De Morgan: NOT(A AND B) = (NOT A) OR (NOT B) · NOT(A OR B) = (NOT A) AND (NOT B)
  • NAND และ NOR เป็น universal gate (สร้างเกตอื่นได้ทั้งหมด) · A + A'B = A + B · A + A' = 1 · A·A' = 0
  • Half adder: Sum = A XOR B · Carry = A AND B (1+1 → Sum 0 Carry 1) · ลำดับความสำคัญ NOT > AND > OR

ข้อสอบชอบพลิกตรงนี้

  • NAND = "NOT A AND NOT B" ผิด (นั่นคือ NOR) · NAND = NOT(A AND B)
  • XOR ต่างจาก OR ที่ช่อง 1,1 (XOR ได้ 0, OR ได้ 1)
  • NOR กับ XNOR ต่างกันที่ช่อง 1,1 ช่องเดียว (NOR=0, XNOR=1) ใช้ช่องนี้แยกตัวเลือกที่สลับกัน
ตัวอย่างโจทย์พลิก: A=1, B=0 ค่าของ (A NOR B) XOR (A NAND B) คือเท่าใด
วิธีตัด: คิดวงเล็บในก่อน NOR(1,0)=0 · NAND(1,0)=1 · แล้ว XOR(0,1)=1 → ตอบ 1

3. ฮาร์ดแวร์และสถาปัตยกรรม

ต้องจำ

  • CPU = CU (ควบคุม/ถอดรหัสคำสั่ง) + ALU (คำนวณ/เปรียบเทียบเชิงตรรกะ) + Register (เก็บชั่วคราวในซีพียู เช่น PC เก็บที่อยู่คำสั่งถัดไป)
  • วงจรคำสั่ง: Fetch → Decode → Execute (→ Store) · Von Neumann: โปรแกรมกับข้อมูลอยู่หน่วยความจำเดียวกัน · Harvard: แยกกัน
  • ความเร็ว เร็ว → ช้า: Register > Cache (L1 > L2 > L3) > RAM > SSD > HDD > เทป · ยิ่งเร็วยิ่งเล็กและแพง
  • RAM: อ่าน/เขียนได้ volatile (ไฟดับข้อมูลหาย) · DRAM ใช้เป็นหน่วยความจำหลัก (ต้อง refresh) · SRAM เร็วกว่า ใช้ทำ Cache
  • ROM: non-volatile เก็บ BIOS/firmware · EPROM ลบด้วยแสง UV · EEPROM/Flash ลบด้วยไฟฟ้า
  • Cache hit = พบข้อมูลใน Cache · miss = ต้องไปอ่าน RAM
  • Bus: Address ทิศทางเดียว (CPU → หน่วยความจำ) กำหนดจำนวนที่อยู่ = 2^n · Data สองทิศทาง · Control ส่งสัญญาณ read/write
  • Address bus 32 บิต → 2³² byte = 4 GB · 16 บิต → 64 KB · ความเร็วซีพียู 3 GHz = 3,000,000,000 รอบนาฬิกาต่อวินาที

ข้อสอบชอบพลิกตรงนี้

  • สลับ RAM/ROM ว่า volatile ตัวไหน · สลับ Address/Data bus ว่าทิศทางเดียวหรือสองทาง
  • ขนาดหน่วยความจำสูงสุดดูจากความกว้าง address bus ไม่ใช่ data bus
  • เร็วสุดคือ Register (ไม่ใช่ Cache) · Cache มีขนาดเล็กกว่า RAM เสมอ · จำนวน core มากไม่ได้แปลว่าเร็วกว่าเสมอ
ตัวอย่างโจทย์พลิก: ซีพียูมี address bus 32 บิต อ้างที่อยู่ระดับ byte ได้สูงสุดเท่าใด (ก) 32 MB (ข) 1 GB (ค) 4 GB (ง) 32 GB
วิธีตัด: 2³² = 4,294,967,296 byte = 4 × 2³⁰ → (ค) · ห้ามตอบตามตัวเลข 32 ตรง ๆ

4. ระบบปฏิบัติการ

ต้องจำ

  • หน้าที่ OS: จัดการ process · หน่วยความจำ · ไฟล์ · อุปกรณ์ I/O · ผู้ใช้/ความปลอดภัย
  • Process states: New → Ready → Running → Terminated · Running → Waiting (รอ I/O) · Waiting → Ready (I/O เสร็จ) · Running → Ready (หมดเวลา) · Ready → Running = dispatch
  • ตัวอย่างคิด (P1=6, P2=8, P3=7, P4=3 มาถึงพร้อมกันที่เวลา 0) ค่าเวลารอเฉลี่ยที่คำนวณแล้ว:

  • เวลารอ = เวลาเสร็จ − เวลามาถึง − burst · turnaround = เวลาเสร็จ − เวลามาถึง
  • Deadlock ต้องเกิดครบ 4 เงื่อนไข: Mutual exclusion · Hold and wait · No preemption · Circular wait (ป้องกันโดยทำลายข้อใดข้อหนึ่ง)
  • Paging: แบ่ง logical เป็น page และ physical เป็น frame ขนาดเท่ากัน · page table แปลง page → frame · เกิด internal fragmentation (หน้าสุดท้ายเหลือ) · segmentation ขนาดไม่เท่ากัน เกิด external
  • Virtual memory: ใช้ดิสก์ขยาย RAM · page fault = หน้าที่ต้องการไม่อยู่ใน RAM · thrashing = สลับหน้าถี่จน CPU แทบไม่ได้ทำงาน · replacement: FIFO, LRU, Optimal
  • คำนวณ: page 4,096 B · ที่อยู่ 10,000 → page 2 offset 1,808 · ถ้า page 2 อยู่ frame 5 → physical = 5×4096 + 1808 = 22,288 · process 10,000 B ใช้ 3 page เสียที่ว่าง 2,288 B

ข้อสอบชอบพลิกตรงนี้

  • Waiting → Running ไม่ได้ ต้องผ่าน Ready ก่อน
  • เงื่อนไข deadlock คือ "No preemption" ตัวเลือก "Preemption" เป็นตัวหลอก · starvation ≠ deadlock (starvation ไม่ได้รอกันเป็นวงจร)
  • Paging เกิด internal ไม่ใช่ external · Belady's anomaly: FIFO เพิ่ม frame แล้ว fault เพิ่มได้ (ลำดับ 1,2,3,4,1,2,5,1,2,3,4,5 → 3 frame = 9 ครั้ง, 4 frame = 10 ครั้ง)
ตัวอย่างโจทย์พลิก: ข้อใดไม่ใช่เงื่อนไขที่ทำให้เกิด deadlock (ก) Mutual exclusion (ข) Hold and wait (ค) Preemption (ง) Circular wait
วิธีตัด: จำ 4 ข้อให้ครบ ข้อที่เกินคือคำที่ขาด "No" → ตอบ (ค)

7. โครงสร้างข้อมูล

ต้องจำ

  • Stack = LIFO (push/pop/peek) ใช้กับ undo, call stack, DFS, คำนวณ postfix · Queue = FIFO (enqueue/dequeue) ใช้กับคิวพิมพ์, scheduling, BFS
  • Preorder = ราก–ซ้าย–ขวา · Inorder = ซ้าย–ราก–ขวา · Postorder = ซ้าย–ขวา–ราก · Level-order (BFS) ใช้ queue
  • BST: inorder ได้ค่าเรียงน้อย → มาก (ใส่ 50,30,70,20,40,60,80 → inorder 20 30 40 50 60 70 80 · preorder 50 30 20 40 70 60 80)
  • ต้นไม้ไบนารี n ระดับ (รากเป็นระดับ 1) มีโหนดได้สูงสุด 2^n−1 (3 ระดับ = 7)
  • Infix → postfix: (A+B)*C → AB+C* · 2+3*4 → 2 3 4 * + = 14 · ประเมิน postfix: เจอตัวเลข push เจอเครื่องหมาย pop สองตัว
  • Array เข้าถึงตามดัชนี O(1) แทรกกลาง O(n) · Linked list เข้าถึง O(n) แทรก/ลบ (เมื่อมีตำแหน่งแล้ว) O(1) · Hash table ค้นเฉลี่ย O(1)

ข้อสอบชอบพลิกตรงนี้

  • ลำดับสั่ง push 1, push 2, pop, push 3, pop → stack ออก 2 แล้ว 3 เหลือ [1] · queue (enq 1, enq 2, deq, enq 3, deq) ออก 1 แล้ว 2 เหลือ [3]
  • โหนดที่มีลูกคนเดียว ต้องดูว่าเป็นลูกซ้ายหรือขวา เพราะมีผลต่อ inorder
  • BFS ใช้ queue · DFS ใช้ stack (สลับกันบ่อย)
ตัวอย่างโจทย์พลิก: ต้นไม้ A เป็นราก ลูกซ้าย B ลูกขวา C · B มีลูกซ้าย D ลูกขวา E · C มีลูกซ้ายคือ F ตัวเดียว · ผล inorder คือ
วิธีตัด: ซ้ายสุดก่อน: D B E → แล้วราก A → แล้วต้นไม้ย่อย C: F C → D B E A F C (preorder A B D E C F · postorder D E B F C A)

ข้อสอบชอบพลิกตรงนี้

  • Merge sort best = average = worst (ไม่แปรตามลักษณะข้อมูล) · Quick sort worst เป็น O(n²) ไม่ใช่ O(n log n)
  • Insertion sort ถ้าข้อมูลเรียงอยู่แล้วเป็น O(n) · Selection sort เรียงแล้วก็ยัง O(n²)
  • ตำราบางเล่มให้ Bubble best = O(n²) (ไม่มี flag) ให้ใช้ตามเงื่อนไขที่โจทย์เขียน
ตัวอย่างโจทย์พลิก: ข้อมูล 1,000 ตัวเรียงน้อยไปมากอยู่แล้ว วิธีใดเรียงซ้ำได้เร็วที่สุด (ก) Selection (ข) Insertion (ค) Bubble ไม่มี flag (ง) Quick เลือก pivot ตัวแรก
วิธีตัด: (ก)(ค) ทำ O(n²) เสมอ · (ง) เข้า worst O(n²) พอดี · (ข) O(n) → ตอบ (ข)

11. กฎหมายและจริยธรรมดิจิทัล

ต้องจำ

  • พ.ร.บ.ว่าด้วยการกระทำความผิดเกี่ยวกับคอมพิวเตอร์ พ.ศ. 2550 (แก้ไขเพิ่มเติม พ.ศ. 2560) ความผิดหลัก: เข้าถึงระบบ/ข้อมูลที่มีมาตรการป้องกันโดยมิชอบ · เปิดเผยรหัสหรือมาตรการป้องกันโดยมิชอบ · ดักรับข้อมูลระหว่างทาง · แก้ไข/ทำลายข้อมูล · รบกวนระบบ · ส่งข้อมูลปกปิดแหล่งที่มาจนรบกวนผู้รับ (สแปม) · นำเข้าข้อมูลปลอม/เท็จที่น่าจะเสียหาย · ตัดต่อภาพผู้อื่นจนน่าจะเสียชื่อเสียง
  • ผู้ให้บริการต้องเก็บข้อมูลจราจรทางคอมพิวเตอร์ (log) ไม่น้อยกว่า 90 วัน · ผู้ให้บริการที่จงใจสนับสนุนหรือยินยอมให้กระทำผิดมีความผิดด้วย
  • พ.ร.บ.ลิขสิทธิ์ พ.ศ. 2537: ลิขสิทธิ์เกิดทันทีที่สร้างงาน ไม่ต้องจดทะเบียน · โปรแกรมคอมพิวเตอร์เป็นงานวรรณกรรม · คุ้มครองทั่วไปตลอดชีวิตผู้สร้าง + 50 ปีหลังเสียชีวิต · ข้อเท็จจริงและข่าวประจำวันไม่มีลิขสิทธิ์ · ใช้เพื่อการศึกษา วิจัย วิจารณ์ ในขอบเขตที่ไม่กระทบเจ้าของเกินสมควรไม่ถือเป็นการละเมิด
  • พ.ร.บ.ธุรกรรมทางอิเล็กทรอนิกส์ พ.ศ. 2544: ลายมือชื่ออิเล็กทรอนิกส์ที่ระบุตัวเจ้าของและเจตนาได้ มีผลทางกฎหมายเทียบเท่าลายมือชื่อ · ข้อมูลอิเล็กทรอนิกส์ปฏิเสธผลทางกฎหมายเพียงเพราะเป็นข้อมูลอิเล็กทรอนิกส์ไม่ได้
  • PDPA พ.ศ. 2562 (บังคับใช้เต็มรูปแบบ 1 มิ.ย. 2565): คุ้มครองข้อมูลของบุคคลธรรมดา (ไม่ครอบคลุมนิติบุคคล) · เจ้าของข้อมูล (data subject) · ผู้ควบคุมข้อมูล (controller ตัดสินใจวัตถุประสงค์/วิธีการ) · ผู้ประมวลผล (processor ทำตามคำสั่ง controller)
  • ข้อมูลอ่อนไหว (เชื้อชาติ ศาสนา ความเห็นการเมือง สุขภาพ พันธุกรรม ชีวภาพ เช่น ลายนิ้วมือ/ใบหน้า ประวัติอาชญากรรม ฯลฯ) ต้องได้ความยินยอมโดยชัดแจ้ง · สิทธิเจ้าของข้อมูล: เข้าถึง/ขอสำเนา · แก้ไข · ลบ · ระงับ · คัดค้าน · โอนย้าย · ถอนความยินยอม · แจ้งเหตุละเมิดต่อสำนักงานคณะกรรมการคุ้มครองข้อมูลส่วนบุคคลภายใน 72 ชั่วโมง นับแต่ทราบเหตุ (เท่าที่ทำได้)
  • Creative Commons: BY = ต้องให้เครดิต · NC = ห้ามใช้เชิงพาณิชย์ · ND = ห้ามดัดแปลง · SA = ดัดแปลงได้แต่ต้องแจกต่อด้วยสัญญาอนุญาตแบบเดียวกัน · เข้มสุดคือ BY-NC-ND · CC0 = สละสิทธิ ใช้ได้โดยไม่ต้องให้เครดิต

ข้อสอบชอบพลิกตรงนี้

  • "ต้องขอความยินยอมทุกกรณี" ผิด · PDPA ยังมีฐานอื่น เช่น สัญญา ประโยชน์สำคัญต่อชีวิต ภารกิจสาธารณะ ประโยชน์โดยชอบด้วยกฎหมาย การปฏิบัติตามกฎหมาย
  • "ลิขสิทธิ์ต้องจดทะเบียนก่อน" ผิด · "PDPA คุ้มครองข้อมูลบริษัท" ผิด · controller กับ processor สลับกันบ่อย
ตัวอย่างโจทย์พลิก: รูปภาพใช้สัญญาอนุญาต CC BY-SA นำไปดัดแปลงแล้วขายเป็นโปสเตอร์ได้หรือไม่
วิธีตัด: ไม่มี NC → ขายได้ · ไม่มี ND → ดัดแปลงได้ · ต้องให้เครดิต (BY) และแจกต่อใต้ CC BY-SA เดิม (SA) → ตอบ "ได้ โดยมีเงื่อนไข"

12. ฐานข้อมูล

ต้องจำ

  • Primary key: ไม่ซ้ำและไม่เป็น NULL · มีได้ 1 ชุดต่อตาราง (ประกอบหลายคอลัมน์ได้ = composite) · Candidate key = คอลัมน์ที่เหมาะเป็น PK ทั้งหมด · Foreign key อ้างถึง PK ของอีกตาราง (ซ้ำได้ เป็น NULL ได้)
  • Degree = จำนวนคอลัมน์ (attribute) · Cardinality = จำนวนแถว (tuple/record) · relation = ตาราง
  • ER: สี่เหลี่ยม = Entity · วงรี = Attribute · ข้าวหลามตัด = Relationship · ความสัมพันธ์ 1:1, 1:N, M:N (M:N ต้องแตกเป็นตารางเชื่อมที่มี FK สองตัว)
  • Normalization: 1NF = ทุกเซลล์เป็นค่าเดี่ยว ไม่มีกลุ่มซ้ำ · 2NF = 1NF + ไม่มี partial dependency (คอลัมน์ไม่ใช่คีย์ต้องขึ้นกับทั้งหมดของคีย์ผสม) · 3NF = 2NF + ไม่มี transitive dependency (non-key → non-key)
  • ตัวอย่างผิด: ใส่เบอร์โทร 2 เบอร์ในเซลล์เดียว = ผิด 1NF · Order(order_id, product_id, product_name, qty) คีย์ผสม product_name ขึ้นกับ product_id อย่างเดียว = ผิด 2NF · Student(id, dept_id, dept_name) dept_name ขึ้นกับ dept_id = ผิด 3NF
  • กลุ่มคำสั่ง: DDL (CREATE ALTER DROP TRUNCATE) · DML (INSERT UPDATE DELETE และ SELECT ตามตำราส่วนใหญ่) · DCL (GRANT REVOKE) · TCL (COMMIT ROLLBACK)
  • ลำดับเขียน: SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY · ลำดับประมวลผล: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY
  • WHERE กรองแถวก่อนจัดกลุ่ม ใช้ COUNT/SUM/AVG ไม่ได้ · HAVING กรองกลุ่มหลัง GROUP BY ใช้ฟังก์ชันรวมได้ · LIKE: % = กี่ตัวก็ได้ · _ = 1 ตัว · ACID = Atomicity, Consistency, Isolation, Durability
  • DELETE ลบแถว (ใส่ WHERE ได้) · TRUNCATE ลบทุกแถว โครงสร้างอยู่ · DROP ลบทั้งตาราง · INNER JOIN ได้เฉพาะที่จับคู่ · LEFT JOIN ได้ตารางซ้ายครบ ฝั่งขวาไม่เจอเป็น NULL

ข้อสอบชอบพลิกตรงนี้

ตารางตัวอย่าง s(id, name, dept, score) = (1,A,CS,80) (2,B,CS,60) (3,C,IT,70) (4,D,IT,NULL) (5,E,IT,90) · ผลที่รันตรวจแล้ว:

คำสั่งผล
COUNT(*) เทียบ COUNT(score)5 เทียบ 4 (COUNT(คอลัมน์) ข้าม NULL)
SUM(score) · AVG(score)300 · 75 (หาร 4 ไม่ใช่ 5 เพราะข้าม NULL)
WHERE score = NULL0 แถว (ต้องใช้ IS NULL → 1 แถว)
WHERE score != 803 แถว (แถว NULL ไม่ติดมาด้วย)
GROUP BY dept HAVING COUNT(*) > 2IT (3)
  • ตาราง d มี CS, IT, EE → LEFT JOIN แล้วนับ จะเห็น EE = 0 · INNER JOIN จะไม่มี EE
  • "PK ซ้ำได้" ผิด · "FK ต้องไม่เป็น NULL" ไม่จำเป็น · ผู้เรียนมักสลับ degree กับ cardinality
ตัวอย่างโจทย์พลิก: ต้องการแผนกที่มีพนักงานมากกว่า 2 คน: SELECT dept FROM s WHERE COUNT(*) > 2 GROUP BY dept ถูกหรือไม่
วิธีตัด: WHERE ใช้ฟังก์ชันรวมไม่ได้ (รันแล้ว error: misuse of aggregate) → ต้องเป็น GROUP BY dept HAVING COUNT(*) > 2

13. หลักสูตร ว 4.1/ว 4.2 และแนวคิดเชิงคำนวณ

ต้องจำ

  • หลักสูตรแกนกลาง 2551 (ฉบับปรับปรุง 2560) กลุ่มสาระวิทยาศาสตร์และเทคโนโลยี สาระที่ 4 เทคโนโลยี: ว 4.1 = การออกแบบและเทคโนโลยี (design thinking, กระบวนการเชิงวิศวกรรม) · ว 4.2 = วิทยาการคำนวณ (แนวคิดเชิงคำนวณ, อัลกอริทึม, การเขียนโปรแกรม, ข้อมูล, ICT อย่างรู้เท่าทันและมีจริยธรรม)
  • กระบวนการออกแบบเชิงวิศวกรรม: ระบุปัญหา → รวบรวมข้อมูล → ออกแบบวิธีแก้ปัญหา → วางแผนและลงมือทำ → ทดสอบ ประเมิน ปรับปรุง → นำเสนอ
องค์ประกอบแนวคิดเชิงคำนวณความหมาย / คำที่เห็นในโจทย์
Decomposition (แยกย่อยปัญหา)แบ่งปัญหาใหญ่เป็นปัญหาย่อย
Pattern Recognition (หารูปแบบ)สังเกตสิ่งที่ซ้ำ/คล้ายกัน
Abstraction (คิดเชิงนามธรรม)เก็บเฉพาะสาระสำคัญ ตัดรายละเอียดที่ไม่จำเป็น
Algorithm Design (ออกแบบอัลกอริทึม)วางลำดับขั้นตอนแก้ปัญหา

ข้อสอบชอบพลิกตรงนี้

  • ว 4.1 กับ ว 4.2 สลับกัน: ถ้าโจทย์พูดถึงการออกแบบชิ้นงาน/ผลิตภัณฑ์ = ว 4.1 ถ้าพูดถึงอัลกอริทึม/การเขียนโปรแกรม = ว 4.2
  • แนวคิดเชิงคำนวณไม่ได้แปลว่าต้องใช้คอมพิวเตอร์ · ใช้กับการแก้ปัญหาในชีวิตจริงได้ · ตรวจตัวชี้วัดชั้นปีฉบับปัจจุบันที่ ipst.ac.th
ตัวอย่างโจทย์พลิก: แผนที่รถไฟฟ้าแสดงเฉพาะสายและสถานี ไม่แสดงระยะทางจริงและถนน เป็นองค์ประกอบใด
วิธีตัด: ตัดรายละเอียดที่ไม่จำเป็นออก → Abstraction (ไม่ใช่ Decomposition ที่แบ่งเป็นส่วนย่อย)

14. AI · ML · IoT · SDLC (ย่อ)

ต้องจำ

  • AI ⊃ Machine Learning ⊃ Deep Learning (โครงข่ายประสาทเทียมหลายชั้น) · Generative AI สร้างเนื้อหาใหม่ (ระวัง hallucination, อคติ, ลิขสิทธิ์, ข้อมูลส่วนบุคคล)
  • ML 3 แบบ: Supervised (ข้อมูลมีป้ายคำตอบ: classification แยกประเภท · regression ทำนายค่าต่อเนื่อง) · Unsupervised (ไม่มีป้าย: clustering จัดกลุ่ม) · Reinforcement (ลองผิดลองถูกด้วยรางวัล/โทษ)
  • IoT: อุปกรณ์ + เซนเซอร์ → เครือข่าย (Wi-Fi, Bluetooth, 4G/5G) → ประมวลผล/คลาวด์ → แอปหรือ actuator สั่งงาน · MQTT = โปรโตคอลเบาแบบ publish/subscribe
  • Cloud: SaaS (ใช้แอปสำเร็จ เช่น เอกสารออนไลน์) · PaaS (แพลตฟอร์มสำหรับพัฒนา) · IaaS (เช่าเครื่องเสมือน)
  • SDLC: วางแผน → วิเคราะห์ความต้องการ → ออกแบบ → พัฒนา → ทดสอบ → นำไปใช้ → บำรุงรักษา (ตำราบางเล่มรวมเป็น 5–6 ขั้น ให้ดูตามโจทย์) · บำรุงรักษามักยาวและแพงที่สุดในวงจร
  • Waterfall เรียงขั้นย้อนกลับยาก · Prototype สร้างต้นแบบให้ผู้ใช้ดู · Agile/Scrum ทำเป็นรอบสั้น (sprint) ส่งมอบบ่อย · Spiral วนรอบพร้อมประเมินความเสี่ยง
  • ทดสอบ: Black-box ดูแค่ input/output · White-box ดูโค้ดภายใน · ลำดับ unit → integration → system → acceptance (UAT โดยผู้ใช้)

ข้อสอบชอบพลิกตรงนี้

  • Clustering เป็น unsupervised (ไม่ใช่ supervised) · Supervised ต้องมี label · AI กว้างกว่า ML กว้างกว่า DL (ห้ามสลับ)
  • Black-box ไม่ต้องรู้โค้ด · White-box ต้องรู้โค้ด · Waterfall ไม่เหมาะกับความต้องการที่เปลี่ยนบ่อย
ตัวอย่างโจทย์พลิก: ฝึกโมเดลแยกอีเมลสแปม/ไม่ใช่สแปม จากตัวอย่างที่คนติดป้ายไว้แล้ว เป็น ML แบบใด
วิธีตัด: มีป้ายคำตอบ + ผลเป็นหมวดหมู่ → Supervised (classification) ไม่ใช่ clustering
